# lilart-gen — картинки из командной строки

Программа делает картинки тем же движком, что и lil art, но без окна. Нужна, чтобы
Claude (или любой скрипт) мог сам нагенерировать арт пачкой.

- Папка проекта: `~/AI dev/lil/lil-art`. Её настоящий путь `build.sh` вшивает в Info.plist программы (`LilRoot`), а эта утилита находит проект по своему месту в `tools/`; ярлык в домашней папке не нужен.
- Программа: `~/AI dev/lil/lil-art/tools/lilart-gen`
- Исходник: `~/AI dev/lil/lil-art/app/Sources/LilArtGen/LilArtGen.swift`
- Собрать заново: `~/AI dev/lil/lil-art/build.sh gen` (только она, приложение не трогает);
  `~/AI dev/lil/lil-art/build.sh` без слов собирает и приложение, и её.

## Главное правило про память

Модель грузится **один раз — в движок lil art** (`127.0.0.1:7859`). Программа сама
модель не грузит, она только просит движок нарисовать. Krea 2 Turbo (13.4 ГБ) плюс её
кодировщик (4.5 ГБ) помещаются в 24 ГБ только в одном экземпляре, поэтому второй движок
программа не запускает никогда.

## Одна картинка

```bash
~/"AI dev/lil/lil-art"/tools/lilart-gen --prompt "a red apple on a wooden table, studio light" --out ~/Desktop/apple.png
```

```bash
~/"AI dev/lil/lil-art"/tools/lilart-gen --prompt-file prompt.txt --out out/hero.png --seed 42 --width 1024 --height 1536
```

Флаги:

| флаг | что делает | по умолчанию |
|---|---|---|
| `--prompt "…"` / `--prompt-file файл` | текст (одно из двух) | — |
| `--out путь.png` | куда сохранить | `./lilart_<seed>.png` |
| `--model файл.ckpt` | модель из папки моделей | `krea_2_turbo_q8p.ckpt` |
| `--width`, `--height` | размер, **только кратно 64** (64…4096) | 1024 × 1024 |
| `--seed N` | сид 0…4294967295 | случайный, всегда печатается |
| `--steps N`, `--cfg X`, `--sampler имя` | поверх рекомендации модели | рекомендация модели |
| `--negative "…"` | Negative prompt (при CFG 1 ни на что не влияет) | пусто |
| `--timeout сек` | сколько ждать одну картинку | 600 |
| `--port N` | порт движка | как в настройках lil art (7859) |
| `--dry-run` | показать план и настройки, ничего не рисовать | — |
| `--sheet папка/<id>` | только пересобрать лист этого id, без генерации | — |

Шаги, CFG и сэмплер берутся из рекомендации модели, которую отдаёт движок. Для Krea 2
Turbo это 8 шагов, CFG 1, Euler A Trailing (проверено). Сэмплер можно писать как в
движке (`"DDIM Trailing"`, `"DPM++ 2M Karras"`) или слитно (`dDIMTrailing`); регистр и
знаки не важны, полный список печатается, если указать неверное имя.

## Правка картинки (снимок + маска)

```bash
~/"AI dev/lil/lil-art"/tools/lilart-gen --model flux_2_klein_4b_q8p.ckpt --image in.png --mask mask.png \
  --width 1024 --height 704 --prompt "Remove the red car, show the empty street" --out out.png --count 2
```

| флаг | что делает |
|---|---|
| `--image файл` | картинка, которую меняем; движок подгоняет её под `--width/--height` |
| `--mask файл` | белое — перерисовать, чёрное — оставить; переписывается в уровни движка (0/2) |
| `--fresh` | белое рисовать с нуля (уровень 1), а не от того, что там было |
| `--strength 0…1` | насколько перерисовывать; модели, что правят по описанию (FLUX.2, Kontext, Qwen Image Edit/2.1), — 1 |
| `--ref файл` | картинка-образец (moodboard) |
| `--count N` | N вариантов (1…8), сиды seed, seed+1, … → `out_1.png`, `out_2.png`, … |
| `--lora файл:вес,…` | LoRA из папки моделей (через запятую, вес 0…2, по умолчанию 1); свои LoRA модели остаются |
| `--upscaler файл.ckpt`, `--upscale-factor 2\|4` | сразу увеличить результат апскейлером движка (`4x_ultrasharp_f16.ckpt`) |

Только одиночный режим, с `--jobs` не сочетается. Замер 2026-10-22: Flux 2 Klein 4B, 1024×704,
маска на машину — 20 с вместе с запуском движка, машина убрана чисто. Так lil develop делает
«нейрообработку» (`~/lil-develop`).

## Пачка

```bash
~/"AI dev/lil/lil-art"/tools/lilart-gen --jobs jobs.json --out-dir ~/memegame/art/_gen/round1 --limit 80
```

`jobs.json` — список заданий:

```json
[
  {"id": "hero_idle", "prompt": "pixel-art style meme hero, idle pose, plain white background", "count": 4},
  {"id": "boss_cringe", "prompt": "giant cringe boss, cartoon, plain white background", "count": 4, "seed": 1000},
  {"id": "banner", "prompt": "wide game banner with the title area empty", "count": 2, "width": 1536, "height": 640}
]
```

- `id` — латиница, цифры, `.` `_` `-` (это и имя папки, и начало имени файла);
- `prompt` — текст;
- `count` — сколько вариантов (если нет — 1);
- `seed` — необязательно: тогда сиды идут `seed, seed+1, …`; без него каждый случайный;
- `width`, `height` — необязательно, кратно 64; иначе берутся `--width/--height` (1024).

**`--limit N` в пачке обязателен.** Это жёсткий потолок генераций за запуск: больше N
запросов к движку программа не отправит никогда. Считается каждая попытка, включая
неудачную — она тоже тратила видеокарту. Если заданий больше лимита, задания
выполняются по порядку, а хвост урезается; программа заранее пишет, что именно урежет.

Перед дорогим прогоном полезно посмотреть план, не тратя ни одной генерации:

```bash
~/"AI dev/lil/lil-art"/tools/lilart-gen --jobs jobs.json --out-dir ~/memegame/art/_gen/round1 --limit 80 --dry-run
```

### Где лежат файлы

```
<out-dir>/<id>/<id>_<n>_<seed>.png    каждый вариант (n — номер варианта с 1)
<out-dir>/<id>/<id>_sheet.png         лист 1024×1024: все варианты сеткой, номер n в углу
```

Лист пересобирается после каждого id и показывает **все** варианты в папке этого id
(4 штуки → сетка 2×2). Если запустить ту же пачку в ту же папку ещё раз, нумерация
продолжится (5, 6, …), старые файлы не затираются, а лист покажет и старые, и новые.
Если в задании задан `seed`, повторный запуск даст те же картинки — для нового раунда
уберите или поменяйте `seed`.

### Пересобрать лист

Удалили неудачные варианты или переименовали — лист собирается заново без генерации:

```bash
~/"AI dev/lil/lil-art"/tools/lilart-gen --sheet ~/memegame/art/_gen/round1/hero_idle
```

### Что печатается

В stdout — по строке на картинку, поля через табуляцию:

```
OK      hero_idle   1   1234567   81.4  /…/hero_idle/hero_idle_1_1234567.png
FAIL    hero_idle   2   7654321   0.4   <причина>
SHEET   hero_idle   4   /…/hero_idle/hero_idle_sheet.png
DONE    ok=11  failed=1  attempts=12  limit=80
```

Всё остальное (план, рекомендация модели, запуск движка) — в stderr.
Одиночный режим печатает такую же строку `OK` с id `single`.

Код выхода: `0` — всё получилось; `3` — были неудачные картинки или пачка остановлена
(причина — в строках `FAIL` и в stderr); `1` — ничего не начато (ошибка в флагах, в
jobs.json, такой модели нет в папке моделей).

Ошибка одной картинки не останавливает пачку. Но **три ошибки подряд** останавливают её:
это значит, что сломалось что-то общее, и дальше лимит тратился бы впустую. Если движок
не удалось поднять или он не отдал настройки модели, пачка останавливается сразу — такие
попытки в лимит не идут, потому что до видеокарты запрос не дошёл.

### Долгие прогоны

Замер 2026-10-11: одна картинка 1024² на Krea 2 Turbo — **81 с** (по журналу движка у
самого приложения в этот день столько же, 60–100 с: похоже, модель между запросами не
остаётся в памяти и грузится заново). Значит, пачка из 80 штук — около двух часов.
Поэтому из Claude Code её надо запускать в фоне (`run_in_background`) и читать вывод по
мере появления строк — вывод построчный, каждая строка появляется сразу. `--timeout`
по умолчанию 600 с на картинку, с запасом.

## Если движок не запущен

1. Программа стучится в `127.0.0.1:<порт>` (порт — из настроек lil art, обычно 7859).
2. Отвечает — работает через него. Чей это движок (lil art или чей-то ещё), неважно; в
   конце она его **не трогает**.
3. Не отвечает, но процесс движка уже есть (например, lil art как раз его запускает) —
   ждёт до 2 минут, пока он ответит. Второй копии не запускает.
4. Движка нет совсем — запускает его сама, ровно как lil art:
   `<папка проекта>/engine/gRPCServerCLI-macOS <папка моделей> --address 127.0.0.1 --port 7859 --weights-cache <как в настройках lil art>`.
   Только `127.0.0.1`, никогда `0.0.0.0` — снаружи машины движок не виден. Его вывод
   дописывается в `engine.log` в папке проекта. Ждёт до 2 минут, пока он ответит.
5. В конце (и при Ctrl-C / `kill`) останавливает движок, **только если запускала его сама**.
   После `kill -9` движок может остаться висеть в памяти — lil art убирает такой при
   следующем запуске, или вручную: `pkill -f gRPCServerCLI-macOS`.

Чего не делать во время пачки: открывать или закрывать lil art. Открытие lil art
перезапускает движок (приложение гасит любой чужой экземпляр), и текущая картинка
упадёт. Если движок пропал посреди пачки, программа поднимет его заново (не больше
трёх раз за запуск).

## Свой VAE или кодировщик (без движка и без генерации)

Дообученную копию стандартной части установленной модели (VAE, текстовый кодировщик, CLIP)
можно перевести в формат движка и отсюда — это та же конвертация, что в окне «Модели»:

```
~/"AI dev/lil/lil-art"/tools/lilart-gen --check-part файл.safetensors    # только сверить слои, ничего не пишет
~/"AI dev/lil/lil-art"/tools/lilart-gen --import-part файл.safetensors   # сверить и положить в папку моделей
```

`--check-part` печатает по строке на каждую подходящую по размерам стандартную часть:
`MATCH|PARTIAL  <стандартный файл>  <слот>  <совпало>/<всего>  min=… mean=…  <как читались слои>`.
`MATCH` — все слои нашли пару; `min` у дообученной копии обычно выше 0.95. `--import-part`
выбирает часть с наибольшим `mean` и печатает `PART  <новый файл>  <слот>  <вместо чего>  <секунды>`.

Сверка занимает секунды. Запись крупного кодировщика в 8 бит (q8p) — около 20 минут на всех
ядрах; VAE — секунды. Новая часть выбирается в lil art: PRO у модели → «VAE» /
«текстовый кодировщик». Список добавленных частей — `lil-parts.json` в папке моделей.

## Сжать модель и сверить слои (без движка и без генерации)

```
~/"AI dev/lil/lil-art"/tools/lilart-gen --squeeze модель.ckpt --plan 4/8 --out копия.ckpt
```

`--plan основная/важные` — биты: 8, 6, 5, 4, 3. Важные — модуляция и по 2 первых и последних блока.
Пишет только в `--out`, папку моделей не трогает. В конце сверяет каждый слой с оригиналом:
`SQUEEZE <файл> <размер> mean_err=… worst_err=… <худший слой>` (относительная ошибка чисел).
Для Wan 1.3B 4/8: 3.1 → 0.93 ГБ за 90 с, mean 1.8%, worst 6.9%. В приложении то же самое —
«Модели» → у модели «Сжать…», и «сжимать новые» для импорта.
